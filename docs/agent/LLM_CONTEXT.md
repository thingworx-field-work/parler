# What goes into the LLM (and how it differs from AGENT-CONTEXT.md)

| Audience | Medium | Sent to the model at runtime? |
|------|------|----------------------|
| **People / Cursor / contributors** | **`./AGENT-CONTEXT.md`** and design docs in the same directory | **No** — repository and IDE reference; not automatically bundled into the prompt |
| **LLM** | **①** **`AgentSettings.systemPrompt`** (per-call override replaces the first segment only)<br>**②** Optional **`appendBuiltInToolRoutingGuide`** appendix<br>**③** Cached/model-stable suffix: optional taxonomy Markdown, GenericThing template names, `GetAlertPrompt`, the unified skill/playbook workflow catalog, `ParlerTimeAnchor.STABLE_TIME_GUIDANCE`, and the final-answer evidence rule. These are folded into the **leading** system row by **`LeadingStablePromptComposer`**. **④** Per-turn framed suffix rows: `/Skill` bodies followed by host-scope observations; then one non-empty resolved user message. A registered slash-only message retains its trimmed raw directive (for example `/Demo`) while its skill body remains in the suffix. | **Yes** — assembled in **`AgentThing.buildLlmTurnContext`** via `resolveModelFacingUserContent`. No wall-clock read participates in leading-row fallback assembly. |
| **LLM** (each provider API call) | **⑤** Framed data-only task evidence, optional retrieval-coverage instruction, and one framed **time context** row | **Yes** — **`AgentLoop`** inserts them before planning and removes them in `finally`. The time row always contains `now_utc`; valid zones add `now_local` and `user_timezone`. Both serializers relocate every classified row to the terminal suffix in authority order: skill, observations (host then evidence), instruction, time. Anthropic rejects any residual null/trim-empty ordinary user row before grouping; valid AgentLoop requests keep every substantive user row as a block array and mark current/previous frontiers before the suffix (≤4 markers total including stable system/tool); false-kind callers retain non-empty ordinary strings. OpenAI/Azure retains system-role rows. |

## Built-in “tool routing” appendix

- **Resource files (shipped with JAR):** `src/main/resources/com/thingworx/things/agent/llm_tool_routing_guide.txt` (identity/scope, discovery and service calls, cached data and deterministic calculations, charts and property history, document knowledge) and `llm_replay_format_routing_guide.txt` (the five compact `$format` result formats).
- **Load logic:** `com.thingworx.things.agent.llm.LlmRoutingGuide`; assembled by `LeadingStablePromptComposer` in the order documented in `./system-prompt-cache.md` §Stable Prompt Ordering.
- **Concatenation:** `your systemPrompt` + `\n\n---\n` + routing guide + `\n\n---\n` + replay-format guide, followed by the cached stable suffix blocks.
- **Disable:** On the **`AgentSettings`** Thing, set **`appendBuiltInToolRoutingGuide`** to **false** (drops both bundled guides; the cached suffix blocks are unaffected).
- **Shape and volume:** The bundled text is the concise form: one owner per rule, `## `-headed sections, no repository-path citations, no Java class names, no historical phase labels. Per-tool calling semantics (parameter lists, enums, caps) live in the advertised tool descriptions and are not repeated here; the guide carries cross-tool routing and evidence-interpretation rules only. Alert routing is owned by `GetAlertPrompt` (`tools/AlertPromptDefaults.DEFAULT_ALERT_PROMPT_MARKDOWN`), time rules by `ParlerTimeAnchor.STABLE_TIME_GUIDANCE`, and the answer-grounding rules by `LeadingStablePromptComposer.FINAL_ANSWER_EVIDENCE_RULE`.
- **Maintenance:** Long planning notes stay in **`docs/agent/*.md`**; to change model behavior, sync **actionable conclusions** into the owning block above (or into **`systemPrompt`**). Do not re-add a rule to the guide when the advertised tool description already states it. **Model tags** conventions are in **`./tags_in_agent_tools.md`**.

### Cross-tool rules the guide owns

- **Cached-tabular routing:** reuse a cached table when it already has the requested columns and scope; aggregate, rank, group and threshold with `tabulate_cached_result` / `summarize_cached_result` over the full table, never from remembered values or sampled rows; re-query only for fresh data or a changed scope/filter. The rule is generic — it does not encode prompt-specific tool-pair bans.
- **Charts / numeric history:** real `startTime`/`endTime` bounds for a requested interval; `requestedTimeRange` is only a chart-domain fallback; qualifying tabular sources, `last_invoke` latest-wins scope, cacheId provenance, multi-chart completion and `build_history_overlay_chart` routing — see the “Charts and property history” section and **`docs/agent/history-overlay-chart.md`**.
- **Time:** relative-argument and precedence rules are owned by the time block, not repeated per tool.

## Tool definitions themselves

**Azure OpenAI**, **OpenAI Chat Completions** (`CHATGPT` provider), and **Anthropic Messages** (`ANTHROPIC`) all receive **`ToolDefinition`** name / description and parameter schemas (built-ins as JSON Schema; Anthropic maps to **`input_schema`**). Division of labor: **tool descriptions** carry per-tool call semantics (parameters, cache handles, chart source rules); **`llm_tool_routing_guide.txt`** carries cross-tool routing (taxonomy-first, chart vs history overlay, cached-table computation). **`invoke_service`** vs **`list_entities_by_type`** choice is split between both; other cross-tool rules rely on the appendix + **`systemPrompt`**.
