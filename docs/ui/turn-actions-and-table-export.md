# Turn actions and table export polish

Status: implemented.
Scope: `parler-ui`, `parler-ui-widget`, `parler-agent` table-export sidecar, and conversation history marker services.

## 1. Goal

This document covers two small but user-visible behaviors:

1. Large table CSV export does not show internal FileRepository directory errors in the table footer.
2. Completed final assistant responses expose compact row actions: copy, print, thumbs up, thumbs down, info, and cut off.

The feature is not a reporting system, not server-side PDF generation, and not a new conversation archive product.

## 2. Background

A footer such as the following is what the export hardening prevents:

```text
Showing 145 of 545 rows -- Directory does not exist: /Administrator/20260521/
```

The first half is generated by `parler-ui` from `shownRows` / `totalRows`.
The second half is `TableBlock.exportMessage`.

The agent creates export paths like:

```text
/Administrator/20260521/<timestamp>_<requestId>.csv
```

`ParlerTableFileExportHook` checks path collision with `GetFileListing(parent, "")` before `SaveText`.
When the parent directory does not exist, `GetFileListing` throws; ThingWorx `SaveText` creates parent directories itself,
so a missing parent must not block the export.

Export failures do not change the live in-memory LLM message list; they only affect stream sidecar / UI export metadata.

## 3. CSV Export Behavior

### 3.1 Required behavior

When `exportFileRepository` is configured and a table qualifies for CSV export:

- If the generated parent directory does not exist, export should still succeed.
- If the target file does not exist, `SaveText` should write the CSV.
- If the target file exists, collision handling should still pick an alternate file name.
- If the repository is missing or permission prevents writing, keep a warning log and set export status, but do not surface raw Java exception text in the UI footer.

### 3.2 Implementation

1. In `ParlerTableCsvPathCollisions.repositoryFileExists(...)`, treat "directory does not exist" from `GetFileListing` as `false`.
2. The classification recognizes the `Directory does not exist` exception shape explicitly and is covered by tests.
3. Keep other `GetFileListing` failures as export warnings.
4. There is no separate **`CreateFolder`** preflight before **`SaveText`** for parent directories: ThingWorx **`FileRepositoryThing.SaveText`** creates missing parent directories under lock.
5. If **`SaveText`** fails because of permissions, quota, or repository problems, the export is unavailable and no partial write is attempted.
6. Write failures replace the raw `exportMessage` with a short product-safe message:

```text
CSV export unavailable.
```

The full exception remains in `ApplicationLog`.

`CONTRACTS/TABLE_CONTRACT.md` specifies the same rule: missing parent directory during collision detection is
treated as "target file absent", and normal UI export messages must not include raw repository paths, exception class names,
or Java exception text.

### 3.3 UI footer

The table footer should remain focused on user-facing facts:

- `Showing N of M rows`
- `Download CSV` link when export succeeds
- short export unavailable text only when useful

Do not show raw repository paths or Java exception text in the normal table footer.

`parler-ui` should also defend against regressions: if an agent accidentally sends an unsafe raw export message, the footer
should not concatenate it into the visible `Showing N of M rows` text. Keep an allowlist or equivalent product-safe mapping
for known export statuses.

## 4. Assistant Row Actions

`Copy` / `Print` behavior ([`assistant-response-actions.md`](./assistant-response-actions.md)) is the base; the strip changes its visual treatment and adds four actions.

Actions in order:

1. `copy`
2. `print`
3. `thumbs up`
4. `thumbs down`
5. `info`
6. `cut off`

### 4.1 Visual treatment

Use a quiet, compact action strip at the bottom of completed final assistant rows.

- Desktop visual height: about 28-32 px.
- Use compact icon or icon+short label buttons.
- Text labels may be visible for `Copy` / `Print`; feedback and info can be icon-first with tooltips.
- Keep touch targets usable on coarse-pointer devices.
- The action strip should not be a large card or panel.
- Do not show actions for active streaming rows, task-state-only rows, transient tool rows, or provider-error placeholders that are not final assistant answers.
- Do not include the action strip itself in copied HTML or printed output.

This compact strip replaces the larger `Copy` / `Print` buttons.

### 4.2 Copy

Keep current copy semantics:

- Copy the final assistant markdown as `text/plain`.
- Copy rendered HTML when clipboard APIs allow it.
- Do not include raw tool JSON.
- Do not require an agent round trip.

### 4.3 Print

Keep current print semantics:

- Print the visible assistant row: charts, tables, markdown, and visible export links.
- Exclude action buttons, task-state panels, transport status, HITL internals, and raw tool JSON.

### 4.4 Feedback

Thumbs up/down is not an LLM message and must not be rehydrated into LLM context.

Feedback is an append-only event stream with last-win UI semantics.

Persistence:

- Append one event row to `AgentMessageStream` with `role = "ui_feedback"`.
- There is no separate feedback DataTable.
- `content` is compact JSON:

```json
{
  "type": "assistant_feedback",
  "conversationId": "...",
  "requestId": "...",
  "assistantMessageId": "...",
  "previousRating": "down",
  "rating": "up",
  "createdAt": "2026-05-21T20:45:00Z"
}
```

Rules:

- `assistantMessageId` must be a server-generated, server-stored, server-emitted stable id for the final assistant row.
- Add it to the persisted assistant Stream row data shape (for example `AgentMessageData.assistantMessageId`) and populate it
  when the final assistant row is appended.
- Live wire rows and history hydrate rows must both carry the same `assistantMessageId`.
- No backfill is required for Stream rows that existed before this field. Feedback actions should be hidden when a visible
  assistant row has no stable `assistantMessageId`; older rows remain readable/copyable/printable.
- Do not use transient export ids such as `hist-1`, sequence counters, or UI-generated ids for feedback anchoring.
- `requestId` is turn telemetry and useful for logs / debugging. `assistantMessageId` is the feedback anchor and row identity.
  Feedback lookup and last-win state must key by `assistantMessageId`, not by `requestId`.
- On history load, the client reads all feedback events for a visible assistant turn and applies **last-win** ordering by
  server timestamp, then Stream insertion order as the deterministic tie-break. The latest event is the UI memory state for
  that turn.
- A new final assistant turn starts with no selected feedback state.
- When the user clicks up or down, the UI may optimistically update the in-memory state and animate the selected action
  before the append returns.
- Clicking a different action changes the UI memory state and appends a new event.
- Clicking the same selected action does not change the UI memory state, but still appends a new event and may animate as
  a confirmation. There is no "clear rating" state.
- `previousRating` is `"up"`, `"down"`, or `null` when the UI has no confirmed prior rating for that assistant message.
- Consumers use the latest event for the same `assistantMessageId` as the current rating. Older events remain useful audit
  / training signal and are not updated in place.
- `AgentConversationRehydrator` must explicitly ignore `ui_feedback`.
- `AgentMessageStreamHistoryExporter` must explicitly ignore `ui_feedback` in turn segmentation / transcript rendering.
- No Stream-to-LLM replay path lets `ui_feedback` enter prompt assembly.
- No free-text feedback.

Service:

```text
RecordAssistantFeedback(conversationId, assistantMessageId, rating, requestId, previousRating)
```

Expose the feedback service through the same AgentThing / gateway surface that the widget uses for `ClearConversation`-style
conversation operations. Do not ship a service that is only callable from Composer if the widget cannot use it.

The service must validate:

- `rating` is `up` or `down`
- `assistantMessageId` exists on a final assistant row in the same `conversationId`
- the row belongs to the same AgentThing path used by the existing conversation services

Use a bounded lookup for validation so a bad client cannot force an unbounded Stream scan. If validation fails, reject with a
product-safe error and do not append a feedback event.

Client click control:

- Rapid appends per assistant row are throttled: after sending one feedback event, further feedback clicks on that row are
  ignored for **500 ms**.
- If the append fails, keep the visible optimistic state only if the UI shows a small failure indicator; otherwise revert
  to the last confirmed state.

### 4.5 Info

The info action opens a small popover for the selected final assistant row.

Fields:

- provider Thing name
- model/deployment label
- request id
- conversation id
- LLM rounds for the turn
- tool call count
- elapsed latency for the turn
- prompt/input tokens
- completion/output tokens
- cached tokens when available
- local rate-control wait time when available
- compaction ratio when available

Shipped telemetry: when the server attaches sanitized **`llmUsage`** / live **`done.llm_usage`** (subset of Stream **`llmUsageJson`**), the gateway **turn details** popover **MUST** render those token / cache / provider-identity numbers and **MUST NOT** invent estimates. Fields above without server data remain optional (omit placeholders).

Do not include:

- system prompt text
- raw tool payloads
- API keys or headers
- hidden provider request body

Persistence:

- Prefer a sidecar JSON on the final assistant row, built from already-known `LLM_USAGE`, turn timing, and task-loop counters.
- Do not scrape `ApplicationLog` from the UI.
- A field listed above is an allowed field, not a promise to render an empty placeholder. The popover shows only fields that
  are populated.

### 4.6 Cut off

The cut-off action sets the conversation's effective history boundary to the selected final assistant row's completed time.

Expected result:

- The current UI can remove rows up to and including that answer immediately.
- Later UI hydrate skips rows at or before that cutoff.
- Later LLM rehydrate skips rows at or before that cutoff.
- Stream rows remain physically present for audit/debug.

Service:

```text
SetConversationHistoryCutoff(conversationId, cutoffAt)
```

Use this independent service instead of overloading `ClearConversation`. `ClearConversation` remains "clear at now";
`SetConversationHistoryCutoff` means "advance the effective history floor to this completed assistant row".

Implementation:

- Reuse the existing `AgentThreadDataTable.historyClearedAt` semantics.
- Validate that the conversation row exists and belongs to the current user path where existing gateway services require ownership.
- Fail without side effects when an active HITL pending exists for that conversation, matching `ClearConversation`.
- The HITL-pending failure should throw / return a structured, stable error code such as `CUTOFF_BLOCKED_HITL_PENDING` so the
  UI can show a specific product message.
- Only allow the marker to advance. If `historyClearedAt` is already later than or equal to `cutoffAt`, return a product-safe
  no-op success with the existing marker; do not widen effective history. Undo is out of scope.
- Use the same boundary rule as existing clear/hydrate behavior. If Stream `startDate` is inclusive, readers should apply the
  existing `historyClearedAt + 1ms` style rule so the selected row and earlier rows stay hidden.
- The `cutoffAt` instant is the selected final assistant row's server completion / Stream row timestamp, not local browser time.
- Clear JVM conversation state and tabular cache mirrors for that conversation after updating the marker.

Because submit/continuation and clear-style operations share `parlerConversationLock(conversationId)`, a cutoff request made
while a turn is running may wait for that turn to finish. The UI should show a local loading/waiting state rather than creating
a second competing cutoff path. The action strip is visible only on completed rows, so normal users should rarely hit this
except during race conditions.

## 5. Implementation

Touchpoints:

- `ParlerTableFileExportHook`
  - missing-directory classification during collision detection (treat as empty listing for collision checks; no separate
    `CreateFolder` preflight — `SaveText` creates parents)
  - product-safe export messages for listing / folder / write failures
- `AgentMessageData` DataShape / entity metadata
  - nullable `assistantMessageId`
  - old rows may read as empty; no backfill
- `AgentMessageStreamAppender`
  - generate and persist `assistantMessageId` once for final assistant rows
  - pass the same id into the live AlwaysOn payload
- `AgentMessageStreamHistoryExporter`
  - export persisted `assistantMessageId` and sanitized `llmUsage` (from Stream `llmUsageJson`) when present
  - keep `requestId` only as turn telemetry when needed
  - strip or skip `ui_feedback` before chart/table tool-row parsing
- `AgentConversationRehydrator`
  - explicitly ignore `ui_feedback`
- `AgentMessageStreamReader`
  - no filtering of its own; every Stream-to-LLM consumer filters
- `AgentThing` and the widget-facing gateway surface used by current conversation services
  - `SetConversationHistoryCutoff(conversationId, cutoffAt)`
  - `RecordAssistantFeedback(conversationId, assistantMessageId, rating, requestId, previousRating)`
- `AgentThreadDataTableSupport`
  - reuse `markHistoryCleared` for monotonic cutoff behavior
- `parler-ui`
  - compact action strip
  - footer export-message hardening
  - feedback state hydrate / last-win tie-break
  - info popover that renders populated fields only
  - copy/print cleanup that excludes the action strip

## 6. Wire / Contract Notes

- `CONTRACTS/UI_CLIENT_PROTOCOL.md`: stable `assistantMessageId`, feedback-sidecar behavior, and the info fields exposed on
  completed assistant rows.
- `CONTRACTS/API_CONTRACT.md`: `SetConversationHistoryCutoff` / `RecordAssistantFeedback` service payloads where they are
  exposed through gateway wire/service contracts.
- `CONTRACTS/TABLE_CONTRACT.md`: missing-parent export collision behavior and product-safe export messages.
- `docs/agent/conversation-continuity.md`: explicit `ui_feedback` skip semantics, monotonic cutoff, and the timestamp
  boundary rule.

The contract surface is narrow. The feedback and info actions should not introduce a new general analytics subsystem.

## 7. Tests

Agent tests:

- `ParlerTableFileExportHook`: missing parent directory during collision check is treated as file absent.
- `ParlerTableFileExportHook`: successful `SaveText` sets `exportStatus=ok`.
- `ParlerTableFileExportHook` / `ParlerLlmUsageWireSanitizer` / `ParlerTableCsvPathCollisions`: JUnit coverage for collision helpers, CSV char-cap guard, and usage JSON whitelist (no `CreateFolder` dependency).
- `ParlerTableFileExportHook`: write error logs detail but table export message is product-safe.
- Feedback event rows are ignored by LLM rehydrate.
- Feedback event rows do not become assistant transcript rows.
- Feedback last-win ordering is deterministic when two events have the same timestamp.
- Live final assistant rows and hydrated assistant rows carry the same stable `assistantMessageId`.
- Feedback append fails product-safely when `assistantMessageId` is missing or not part of the conversation.
- Cutoff service sets `historyClearedAt` to requested timestamp and clears JVM/caches.
- Cutoff service refuses to move `historyClearedAt` backward.
- Cutoff service fails with `CUTOFF_BLOCKED_HITL_PENDING` or equivalent stable code when active HITL is pending.
- Cutoff and submit/continuation are serialized by the same conversation lock.

UI tests:

- action strip appears only on completed final assistant rows
- small button sizing and no layout shift
- feedback buttons are hidden for older assistant rows without `assistantMessageId`
- feedback click emits the expected service/uplink call
- feedback reconnect restores latest state for each visible `assistantMessageId`
- info popover renders populated metrics (including token usage when `llm_usage` / `llmUsage` is present) and does not show
  empty placeholders for missing fields
- cut off removes effective history after server success
- print output excludes the action strip itself
- table footer does not show raw repository paths or Java exception text even if an unsafe export message is received

## 8. Non-goals

- Server-side PDF.
- Feedback comments.
- Whole-conversation export.
- Physical deletion of stream rows.
- Cross-restart recovery of active UI feedback state beyond the stored event rows.
